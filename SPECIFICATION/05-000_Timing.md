1. Introduction and Language Timeframe
This chapter introduces the timeframe of the Piano programming language to clarify how the execution of a physical action, its duration, and the start of the next action are distinguished. Timing in this language should be understood in terms of the execution meaning of the instructions, not as a general rhythm that necessarily controls all actions simultaneously.
In the press command model, two time parameters have separate roles: duration specifies the duration of the action, and interval specifies the start time of the next command relative to the start of the current action. Therefore, these two parameters are not interchangeable. This chapter describes the general framework; the exact rules for representing and interpreting time values ​​must be defined in the specific timing specification. 2. Scheduling Philosophy: Physical and Relative Time
The Piano programming language focuses on describing physical actions. In this approach, scheduling answers the questions: when does an action start, how long does it stay active, and how does the start of the next instruction relate to its start. This framework supports the definition of time based on the state and sequence of actions, without assuming a single clock or global speed for the entire program in this chapter.
According to the “asynchronous actions” principle in the design principles, the execution of press starts immediately and stays active for the specified duration; the time interval determines the start time of the next instruction. As a result, the next instruction does not necessarily wait for the end of the current action, and there is a possibility of temporal overlap. In contrast, if several actions need to start together, the explicit synchronization principle requires that they be grouped together using the together mechanism; Each action in this group can have its own duration. 3. Fundamental principles: Independence, local control, and determinism
Independence of time parameters. Duration and interval are two independent dimensions of instruction execution. Duration expresses the time that the current action is active; interval expresses the time when the next instruction starts relative to the start of this action. Therefore, changing one does not change the meaning of the other. This independence allows for the expression of consecutive, non-overlapping actions as well as overlapping actions. [File 03-001_Press.md, sections 5 to 7.]
Local control. Time values ​​are placed in the place of instruction parameters, and their relationship is derived from the rules of the instruction itself and the language execution model. This chapter does not assert or define the existence of global speed or tempo commands; the design principles emphasize the primacy of simple, local mechanisms. Any more general rules should be stated in their own specifications, rather than inferred from this introduction. [File 00-002_DesignPrinciples.md, sections 2 and 5; File 03-001_Press.md, section 2.]
Execution certainty. Timing results should obey the explicit rules of the language and execution model. However, the documents reviewed in this collection do not define a complete scheduling algorithm or independent guarantee of determinism for all programs in the scheduling chapter. Therefore, this draft does not declare determinism to be a proven rule; the implementation specification should specify how the order, overlap, and constraints of operators are resolved in each case. 4. The relationship between duration and interval and the mechanism limitation
If the duration of an action is longer than the interval until the start of the next command, the actions may overlap in time. For example, in the documented example of press, when duration is 2. and interval is .2, the key remains active for two seconds, while the next command starts after half a second; so part of the two actions will be simultaneous. This example shows the independence of the two parameters, not a formal definition of the number writing format. [File 03-001_Press.md, section 5.]
If the interval is greater than the duration, based on the roles defined for these two parameters, the end of the current action is placed before the start time of the next command, leaving a gap in the schedule between them. If the two values ​​are equal, the end time of the action coincides with the start time of the next command. This time description alone does not guarantee that any sequence is physically permissible: the operator constraints must also be respected. For example, pressing the same operator again while its previous action is still active may be inconsistent with the operator constraints; overlapping of different operators is also permissible only if it is compatible with the execution schedule. [File 03-001_Press.md, sections 7 and 11.]
To synchronize the start of multiple actions, one should not rely solely on the equality of time values; The explicit together mechanism is intended to group actions that must be initiated together. [File 00-002_DesignPrinciples.md, section 6.]
