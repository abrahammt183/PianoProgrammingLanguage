# Press

## 1. Overview

`press()` is the basic physical action of the Piano Programming Language.

It describes one actuator pressing one keyboard location for a specified duration, with a specified execution mode and interval before the next instruction begins.

The general form is:

```c
press(what, where, duration, how, interval);
```

## 2. Parameters

The parameters of `press()` are:

```text
what
where
duration
how
interval
```

Their roles are:

- `what` — the actuator performing the action.
- `where` — the keyboard location being pressed.
- `duration` — how long the key remains active.
- `how` — how the action is performed.
- `interval` — when the next instruction begins relative to the start of this action.

## 3. Basic Example

```c
press(R1, C4, ., normal, .);
```

This describes:

```text
actuator: R1
key:      C4
duration: .
how:      normal
interval: .
```

The values `.` are inherited from the surrounding context when such a context exists.

## 4. Physical Meaning

A `press()` instruction represents a physical action rather than only a musical note.

For example:

```c
press(R1, C4, ., normal, .);
```

means that the first finger of the right hand presses C4 using normal execution.

## 5. Asynchronous Execution

`press()` is asynchronous.

When a press begins, the key remains active for its specified duration. The next instruction does not necessarily wait for that duration to finish.

The `interval` parameter determines when the next instruction begins.

Therefore, duration and interval are independent concepts.

For example, an action may have:

```text
duration = 2.
interval = .2
```

The key remains active for two seconds while the next instruction begins after half a second.

This allows actions to overlap.

## 6. Duration

The `duration` parameter determines how long the pressed key remains active.

Examples include:

```text
.
2.
4.
.2
.4
.8
```

The detailed representation of timing values is defined by the timing specifications.

`press()` does not require a separate release instruction for normal completion. The action remains active for its duration and then finishes according to the execution model.

## 7. Interval

The `interval` parameter determines when the next instruction begins relative to the start of the current press.

For example:

```c
press(R1, C4, ., normal, .);
press(R2, D4, ., normal, .);
```

The second action begins according to the interval inherited by the surrounding context.

The interval does not specify how long the key remains pressed. That is the purpose of `duration`.

## 8. Inheritance

Each parameter can use `.` when inheritance is supported by the surrounding context.

For example:

```c
press(., ., ., ., .);
```

requests the corresponding values from the surrounding context.

This allows a `press()` action to inherit an actuator, keyboard location, duration, execution mode, and interval without repeating them.

## 9. Relative Values

Values supplied to `press()` may be relative transformations when the surrounding construct permits them.

For example:

```c
press(.[+1], [+1]., ., ., .)
```

can transform the actuator and keyboard location relative to the surrounding values while inheriting the remaining parameters.

Relative transformations are defined in `02-002_RelativeTransformations.md`.

## 10. Multiple Presses

Multiple `press()` statements can be written sequentially:

```c
press(R1, C4, ., normal, .);
press(R2, D4, ., normal, .);
press(R3, E4, ., normal, .);
```

Each statement describes an independent physical action.

Their execution may overlap when their intervals and durations cause their active periods to overlap and the actuator constraints permit it.

## 11. Actuator Constraint

An actuator cannot necessarily begin a new press while its previous press is still active.

For example:

```c
press(R1, C4, 2., normal, .);
press(R1, D4, ., normal, .);
```

may violate the actuator constraints because the same actuator is used while its previous action remains active.

Different actuators may act concurrently.

For example:

```c
press(R1, C4, 2., normal, .);
press(R2, E4, ., normal, .);
```

uses different actuators and may therefore overlap when the execution schedule permits it.

## 12. Press and `together()`

Several presses that must begin simultaneously can be grouped with `together()`.

Example:

```c
together(., ., ., ., .) {
    press(R1, C4, ., normal, .);
    press(R2, D4, ., normal, .);
    press(R3, E4, ., normal, .);
};
```

`together()` synchronizes the beginning of the contained actions.

The individual presses may still have different durations according to the rules of `together()`.

## 13. Press and `repeat()`

`press()` can be used as the body of a repeated pattern.

Example:

```c
repeat(R1, C4, ., R1, .2, 4) {
    press(., ., ., ., .);
    press(.[+1], [+1]., ., ., .)
};
```

The first press inherits the surrounding values.

The second press transforms the actuator and keyboard location relative to the current context.

## 14. `press()` and Musical Notation

A `press()` statement identifies a physical keyboard action.

It does not by itself define staff notation, a chord symbol, a harmonic interpretation, or a musical phrase.

The language instead describes what the performer physically does.

## 15. Parameter Order

The parameter order of `press()` is fixed:

```c
press(what, where, duration, how, interval);
```

Parameter meaning is determined by position.

For example:

```c
press(R1, C4, ., normal, .);
```

means:

```text
what      = R1
where     = C4
duration  = .
how       = normal
interval  = .
```

## 16. Summary

`press()` is the fundamental action for pressing a keyboard location.

Its syntax is:

```c
press(what, where, duration, how, interval);
```

Its parameters are:

```text
what      → actuator
where     → keyboard location
duration  → active time
how       → execution mode
interval  → start interval for the next instruction
```

A `press()` begins asynchronously, remains active for its duration, and schedules the next instruction according to its interval.

It can use explicit values, inherited values, and relative transformations where supported by the surrounding context.
